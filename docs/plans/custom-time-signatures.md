# План: произвольные размеры (кастомные размерности)

## Цель

Дать пользователю выбрать любой размер, а не только четыре встроенных чипа
(`2/4`, `3/4`, `4/4`, `6/8`): например `5/4`, `7/8` или `12/8`. Размер должен
переживать перезапуск приложения и переключаться на лету во время
воспроизведения. Переключение между чипами ряда — одним кликом.

Ряд показывает **максимум 4 чипа**; состав, порядок и список кастомных размеров
управляются в отдельном окне по кнопке-«карандашу» справа от чипов. Кастомные
размеры можно править; порядок видимых чипов настраивается drag-and-drop.

> **Статус:** реализовано в MVP (см. `CHANGELOG.md`, раздел Unreleased).

## Текущее состояние

| Компонент | Что есть |
|---|---|
| `src/app/window.rs` | `TIME_SIGNATURES: [(&str, u32); 4]` — чипы-переключатели; при активации вызывается `params.set_states(beats, &default_states(beats))` |
| `src/model/mod.rs` | `pattern: AtomicU32` упаковывает `(active_mask 16 бит, beat_count 16 бит)` — атомарно для аудиопотока |
| `AppSettings` | Сохраняется только `beats`; знаменатель не хранится |
| `src/audio/scheduler.rs` | Знает только `beat_count`; период тика = `60 / bpm` |
| Окно | `default_width(430)`; ряд 4 чипов + «карандаш» ≈ 348 px — помещается без переносов |

Ключевой факт: **знаменатель нигде не участвует в вычислениях**. «6/8» сегодня —
это 6 тиков на такт, и BPM задаёт частоту каждого тика (восьмых). Это осознанная
простая модель, и план её сохраняет.

## Семантика произвольного размера

Решение (фиксируем):

- **Числитель** — количество тиков в такте, `1..=MAX_BEATS` (сейчас `MAX_BEATS = 16`,
  упирается в 16-битную маску активных долей).
- **Знаменатель** — только подпись единицы доли (`2, 4, 8, 16`). BPM по-прежнему
  означает частоту каждого тика. Это совпадает с текущим поведением `6/8`
  (140 BPM = 140 восьмых в минуту) и не ломает существующих пользователей.

Отвергнутая альтернатива: пересчитывать BPM в зависимости от единицы доли.
Это изменило бы поведение существующего `6/8`, усложнило модель и UI без пользы
для метронома: пользователь слышит тики.

Аудио-движок менять не нужно вообще: он уже умеет любой `beat_count` и
переключение размера на лету (упакованный атомарный `pattern`, есть тест
`meter_change_while_running_keeps_tempo_and_wraps_beat_cycle`).

## UX-решение: ряд быстрых чипов + окно управления

### Ряд чипов

```text
[7/8] [2/4] [4/4] [12/8]  ✎
 └─ до 4 чипов ─────────┘  └─ окно управления
```

- в ряду отображается до **4** чипов из набора «пресеты + кастомные»;
- по умолчанию видны 4 пресета в стандартном порядке (текущее поведение
  не меняется);
- порядок отображения — это порядок списка `visible_meters`; он настраивается
  drag-and-drop в окне управления;
- чипы — `ToggleButton` одной radio-группы; клик = выбор, механика одна для
  пресетов и кастомных;
- **активный размер всегда присутствует в ряду**: в окне управления его
  переключатель видимости заблокирован (тултип «Current meter stays visible»);
- справа — плоская icon-кнопка «карандаш» (`document-edit-symbolic`): это
  **действие**, не выбор; открывает окно управления размерами. Окно создаётся
  при каждом открытии, поэтому всегда подхватывает текущий язык интерфейса.

### Окно управления размерами

`AdwDialog` (ширина ~380, как у окна настроек). Два блока.

**1. Список размеров** — две группы:

| Группа | Содержимое | Drag |
|---|---|---|
| «Shown in the bar» (подзаголовок «Up to 4 chips») | видимые чипы, порядок = порядок ряда | строки перетаскиваются внутри группы |
| «Hidden» | пресеты и кастомные с выключенной видимостью | не перетаскиваются |

Строка на `AdwActionRow`:

| Элемент | Для кого |
|---|---|
| Заголовок «7/8» | все |
| `Switch` «показывать в ряду» | все |
| Кнопка `Edit` (icon) | только кастомные |
| Кнопка `Remove` (icon) | только кастомные |

Правила группы «Shown»:

- больше 4 строк быть не может: при заполненной группе остальные `Switch`
  неактивны;
- переключатель активного размера заблокирован;
- drag-and-drop между строками видимой группы: `DragSource` + `DropTarget`
  на строках `gtk::ListBox`, drop-позиция по верхней/нижней половине строки,
  индикатор вставки подсвечивает границу. Перетащить можно любой видимый чип,
  включая пресеты; в группу «Hidden» переносить нельзя.

Правила удаления кастомного:

- удаление активного кастомного разрешено: метр переключается на `4/4`,
  а если `4/4` скрыт — на первый видимый чип;
- подтверждения нет: размер легко пересоздать.

**2. Редактор кастомного размера** — одна секция с двумя режимами.

Режим **Add** (по умолчанию):

| Элемент | Контрол | Ограничения |
|---|---|---|
| Заголовок | «Add custom size» | |
| Beats | `gtk::SpinButton` 1–16, шаг 1 | по умолчанию 4 или последняя добавленная пара |
| Unit | 4 toggle-кнопки: `2 4 8 16` | по умолчанию 4 |
| Превью | Метка `7/8` | обновляется на каждое изменение |
| Кнопка | `Add` (suggested-action) | добавляет и включает видимость при наличии слота |

Режим **Edit** (после клика `Edit` в строке кастомного):

- заголовок «Edit custom size», контролы заполнены текущей парой, кнопка
  `Save`, рядом `Cancel` (возвращает режим Add);
- `Save` применяет пару к этой записи: подпись чипа обновляется на месте,
  позиция и видимость сохраняются;
- если правится **активный** размер — применённая пара становится активной
  сразу (`set_meter`), паттерн сбрасывается во «все доли включены»;
- конфликт имён: если новая пара совпадает с пресетом или другим кастомным,
  `Save` неактивен с подсказкой «This size already exists» (мерджить записи
  не пытаемся — непредсказуемо для пользователя);
- совпадение с собственным прежним значением — обычный no-op.

Логика `Add`:

- пара совпала с пресетом или уже есть среди кастомных → дубль не создаётся,
  просто включается видимость (если есть слот);
- иначе пара добавляется в кастомные; если в ряду есть свободный слот — чип
  сразу виден, иначе добавлен скрытым (включается в окне);
- выбор нового размера сбрасывает паттерн во «все доли включены» — как у
  пресетов.

### Восстановление и валидация при загрузке

Персистентны: активная пара `(числитель, знаменатель)`, список кастомных
размеров, упорядоченный список видимых. При чтении настроек:

- порядок `visible_meters` сохраняется как есть;
- видимые пары, которых нет среди «пресеты ∪ кастомные», отбрасываются;
- пустой/некорректный список видимых → дефолт: 4 пресета в стандартном порядке;
- список видимых обрезается до 4;
- сравнение активного чипа строго по паре: кастомный `3/8` не подсвечивает
  пресет `3/4`.

## Изменения по файлам

### `src/model/mod.rs`

1. Переупаковать `pattern` в один атомарный `u32`, чтобы сохранить гарантию
   «аудиопоток никогда не видит разорванную пару»:

   ```text
   биты 0..16  active_mask
   биты 16..21 beat_count (1..=16 — пять бит, 16 не влезает в четыре)
   биты 21..24 код знаменателя (0=2, 1=4, 2=8, 3=16)
   ```

2. API: `meter() -> (u32, u32)` (числитель, знаменатель), `set_meter(beats, denominator)`;
   `set_states` сохраняет текущий знаменатель, чипы вызывают
   `set_states` + `set_meter` (или общий `set_meter_and_states`).
3. Списки размеров в `SharedParams` под `Mutex` — аудиопоток их не читает,
   но требование «каждая UI-настройка живёт в `SharedParams`» (см. комментарий
   над структурой) сохраняется:
   - `custom_meters: Mutex<Vec<[u32; 2]>>` (cap 8);
   - `visible_meters: Mutex<Vec<[u32; 2]>>` (cap 4, **упорядоченный**).
4. Методы модели с инвариантами:
   - `custom_meters()`, `visible_meters()`;
   - `set_visible_meters(...)` / `move_visible_meter(from, to)` (reorder);
   - `add_custom_meter(beats, denominator) -> Added | Exists`;
   - `update_custom_meter(index, beats, denominator) -> Updated | Duplicate`
     (проверка дубликата исключает саму правимую запись);
   - `remove_custom_meter(index)`.
   Дедупликация против пресетов и внутри списка, капы 8/4.
5. `AppSettings`:
   - `denominator: u32` с `#[serde(default = "default_denominator")]`. Дефолт
     при чтении старых файлов: `beats == 6 → 8`, иначе `4` — сохраняет смысл
     существующих сохранений без «фреймворка миграций» (удалённого намеренно
     в v0.1.4). Поле пишется всегда.
   - `custom_signatures: Vec<[u32; 2]>` со `#[serde(default)]`;
   - `visible_meters: Vec<[u32; 2]>` со `#[serde(default = "default_visible_meters")]`
     (4 пресета) — с описанной валидацией при загрузке, порядок сохраняется.
6. Тесты: round-trip упаковки, клампы, legacy-дефолт знаменателя,
   `every_setting_survives_a_save_and_reload` + все три новых поля,
   различение `6/4` и `6/8`, лимиты (8 кастомных, 4 видимых), дедупликация,
   `update_custom_meter` (конфликт/обновление активного), reorder + round-trip
   порядка, валидация видимых при загрузке.

### `src/app/window.rs`

1. `TIME_SIGNATURES` → `[(label, beats, denominator); 4]`; пресеты при активации
   выставляют и знаменатель.
2. Ряд: рендер `visible_meters` в их порядке (до 4, radio-группа),
   восстановление активного чипа по паре, кнопка-«карандаш» (`Button` с icon,
   css-класс `flat`).
3. `build_sizes_dialog`: две группы (`AdwPreferencesGroup`), строки
   `AdwActionRow` + `Switch` + `Edit`/`Remove`, drag-and-drop видимых строк
   (паттерн gtk4-rs «ListBox DnD»: `DragSource` + `DropTarget` на строках,
   переносимый payload — позиция строки), редактор с режимами Add/Edit.
4. Fallback при удалении активного кастомного (`4/4`, иначе первый видимый).
5. Новые строки интерфейса в `SettingsText`/`SETTINGS_TEXTS`: `Edit sizes`,
   `Shown in the bar`, `Hidden`, `Up to 4 chips`, `Current meter stays visible`,
   `Add custom size`, `Edit custom size`, `Add`, `Save`, `Cancel`, `Remove`,
   `Edit`, `Beats`, `Unit`, `This size already exists`. Заполнить 25 колонок
   матрицы переводов; для непереведённых языков временно английский текст.
